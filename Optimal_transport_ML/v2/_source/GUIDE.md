# Writing guide — Optimal_transport_ML v2

This guide fixes the tone, the structure and the components of the v2 pages, so that pages written later
stay consistent with `Lesson03.html` (and can be edited without breaking anything).

## 1. The reader and the goal

A master's student who attended the lecture, has the handwritten notes, and wants to **understand
everything and be able to redo every argument**: intuition, meaning of each symbol, step-by-step proofs,
small numerical examples, reflexes for the exam. The v1 companion (`../companion/`) is a dense,
research-style reference with labs; v2 is the pedagogical version, organised exactly like the board.

## 2. Writing rules

1. **English**, second person, short sentences. Define a term at its first use (`<em class="new">`).
2. **Follow the board.** Sections follow the order of the notes. Every statement written in class is quoted
   faithfully in a `board` box with its page (`notes p. N`), then **decoded** symbol by symbol (`dl.decode`).
   Do not invent board content; what is added is presented as such (remarks, refreshers, “going further”).
3. **Why before how:** every notion starts with the problem it solves.
4. **No notion before it is explained.** Prerequisites from earlier lessons go in a folded refresher
   (`details.fold.more`) at the start, or in a `recall` box, saying what is used.
5. **Step-by-step computations** in `ol.steps`, each line with its justification (`span.why`). Never
   “clearly” or “it is easy to see” without the reason.
6. **Idea before proof:** an `idea` box (3–6 lines), then the full proof in `details.fold.proof`.
7. **A worked example with numbers** for every important notion — small, checkable by hand. **Every number
   is checked by computer** (exact LP with POT, closed forms) before it is written.
8. **Pitfalls** (`pitfall`), **reflexes** (`reflex`, “When you see … → …”), **quick checks** (`quiz`) along
   the way; graded **exercises** (★ to ★★★) with hint and full solution at the end.
9. **Sources:** flag gently, in a `remark` box (“Note on the sources”), any typo or convention clash found in
   the PDFs or on the board, with a counter-example or a check.

## 3. Structure of a lesson page

```
pages/LessonNN/00_intro.html      header comment (title, short, description, subtitle, kicker),
                                  objectives, how to read, the story in five steps, refreshers, notation decoder
pages/LessonNN/01_….html …        one file per section (h2 with a stable id), in the order of the notes
pages/LessonNN/1x_exercises.html  exercises
pages/LessonNN/1y_wrapup.html     summary, formula sheet, reflexes, what comes next, glossary EN–FR,
                                  sources and notes on the sources
```
The parts are concatenated in file-name order; formula errors are reported per part, with line numbers.
Add the page to `PAGES` in `build.mjs`.

## 4. Components

Formulas: `$...$` inline, `$$...$$` display (rendered by KaTeX at build time). `\$` for a dollar sign.
An inline formula must not contain an empty line. Long display formulas: split them with
`\begin{aligned} … \\ … \end{aligned}` so that they fit in the 50rem column (the test below reports them).
No circled digits or other characters missing from the KaTeX fonts.

Macros: `\R \N \E \P \X \Y \Z \M` ($\mathcal M_1^+$) `\Pc \U \Lc \B` (Bures) `\al \be \ga \eps \TV \Id \tr
\diam \supp \Lip \argmin \argmax \T \ind \dd \norm{x} \abs{x} \ps{a}{b} \wto \pf{T}{\al}` ($T_\#\alpha$).

```html
<p class="tldr">One sentence that summarises the section.</p>
<div class="box board"><div class="box-h">On the board <span class="ref">notes p. 2</span></div> … </div>
<dl class="decode"><dt>$symbol$</dt><dd>meaning in words</dd> … </dl>
<div class="box def|thm|recall|intu|example|idea|reflex|pitfall|method|remark|summary|objectives">
  <div class="box-h">Title</div> … </div>
<ol class="steps"><li>$$ … $$<span class="why">why this line is true</span></li></ol>
<details class="fold proof|hint|sol|more"><summary>Full proof</summary><div class="fold-body"> … </div></details>
<div class="exo"><div class="exo-h">Exercise N — Title <span class="lvl">★★</span></div> … </div>
<div class="quiz"><p>Question?</p><details class="fold sol"><summary>Answer</summary><div class="fold-body">…</div></details></div>
<div class="cols"> … </div>  <div class="table-wrap"><table> … </table></div>
```

## 5. Figures

**Static figures** are generated by `figures.py` (coordinates computed, never estimated) into `figures/*.svg`
and included with `<figure class="fig"><!-- include figures/name.svg --><figcaption>…</figcaption></figure>`.
Colours are CSS classes only (strokes `c1…c6`, fills `f1…f6`, washes `a1…a5`, text `tx tx-s tx-b tx-i`,
text colours `t1 t2 t3 t5`), so the figures follow the light and dark themes. Colour code of the course:
**α = 2 (orange-red), β = 1 (blue), γ = 5 (purple), maps / interpolations / barycenters = 3 (green)**,
mixtures and total variation = grey.

**Interactive figures** (in `app.js`): `<div class="widget" data-widget="NAME"><p class="w-noscript">…</p></div>`,
followed by a paragraph “What to look at: …”.

| NAME | content |
|---|---|
| `gluing` | three 1D histograms, the two monotone plans, the glued paths $S_{ijk}$ (hover a middle point), glued vs optimal plan, $p\in\{1,2,3\}$, random histograms |
| `zoo` | moving Dirac, Riemann sums, escaping mass (exponent $\gamma$): picture and log–log plot of TV, $W_1$, $W_2$ |
| `interp` | 1D mixture vs displacement interpolation (quantiles), with $W_2$ ratios |
| `bary1d` | 1D barycenter of two inputs by averaging quantiles; densities and CDFs |
| `gauss` | barycenter of three 2D Gaussians, weights by dragging in a triangle, board's $\Psi$ iteration vs Álvarez-Esteban |
| `fixedpoint` | fixed-point algorithm on 40-point clouds (Hungarian assignments), Step / Run, descent check |

## 6. Build and test

```
cd Optimal_transport_ML/v2/_source
npm install                 # KaTeX
python3 figures.py          # static SVG figures (needs numpy)
node build.mjs              # writes ../LessonNN.html; fails on any KaTeX error, missing anchor or duplicate id
node build.mjs Lesson03.html   # one page only
```
Before committing, open the page in a browser (or headless Chromium) and check: no console error, every
widget drawn, no display formula wider than the column at desktop width, light and dark themes, phone width
(no horizontal scroll).
