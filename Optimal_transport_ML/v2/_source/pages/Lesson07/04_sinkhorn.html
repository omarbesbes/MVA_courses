4. Sinkhorn’s algorithm OT4ML §8.2, Algorithm 8.1, pp. 139–141

Fix the rows, then the columns, and repeat: $u\leftarrow a/(Kv)$, $v\leftarrow b/(K\T u)$. Each step costs one matrix–vector product, and the iterates converge to the entropic plan.

The iteration

The scaling equations (8.4), $u\odot(Kv)=a$ and $v\odot(K\T u)=b$, are coupled: $u$ depends on $v$ and conversely. But each one, taken alone, is trivial: if $v$ is known, the first gives $u=a/(Kv)$ (entrywise division); if $u$ is known, the second gives $v=b/(K\T u)$. Sinkhorn’s algorithm solves them alternately.

In the course OT4ML (8.5) and Algorithm 8.1, p. 139 · compact (8.5), p. 34

Sinkhorn’s algorithm solves the two equations alternately: it first updates u to enforce the source marginal and then updates v to enforce the target marginal,

$$u^{(\ell+1)}:=\frac{a}{Kv^{(\ell)}}\qquad\text{and}\qquad v^{(\ell+1)}:=\frac{b}{K\T u^{(\ell+1)}},\qquad(8.5)$$

initialized with any positive vector, for instance $v^{(0)}=\ind_m$. Division is entrywise. Different initializations may select different representatives of the same scaling class, because $(\lambda u,v/\lambda)$ yields the same coupling for every $\lambda>0$.

Algorithm 8.1 (Sinkhorn scaling). Input: positive weights a, b, cost matrix C, regularization $\eps>0$, tolerance tol, iteration budget $L\ge1$. Output: entropic coupling P.
Initialize: set $K_{i,j}=e^{-C_{i,j}/\eps}$, $v^{(0)}=\ind_m$, $r^{(0)}=+\infty$ and $\ell=0$.
While $r^{(\ell)}>\text{tol}$ and $\ell Return $P^{(\ell)}$.

$u^{(\ell+1)}=a/(Kv^{(\ell)})$
The row step: rescale each row of $K\operatorname{diag}(v^{(\ell)})$ so that its sum is $a_i$. After it, the source marginal is exact.
$v^{(\ell+1)}=b/(K\T u^{(\ell+1)})$
The column step: rescale each column so that its sum is $b_j$. It repairs the target marginal and, in general, breaks the source marginal again.
$r^{(\ell)}$
The marginal violation. After a column step the columns are exact, so in practice $r^{(\ell)}=\norm{P^{(\ell)}\ind_m-a}_1$, the row error.
$v^{(0)}=\ind_m$
Any positive start works; it only changes the gauge $(\lambda u,v/\lambda)$ of the limit, never the plan.

The cost of one cycle is two matrix–vector products with a dense $n\times m$ matrix: $O(nm)$ operations. In the book’s words (p. 141), “a chief computational advantage of Sinkhorn’s algorithm, besides its simplicity, is that the only expensive operation is multiplication by the Gibbs kernel”, and “matrix-vector multiplication streams extremely well on GPU”; to solve many problems with the same cost matrix, the matrix–vector products become matrix–matrix products.

Intuition — balancing a spreadsheet

Think of $K$ as a table of preferences and of $a$, $b$ as prescribed row and column totals. Scale the rows to get the right row totals; this spoils the column totals; scale the columns; this spoils the rows, but less; and so on. Survey statisticians do exactly this to adjust a contingency table to known margins (“raking”, or iterative proportional fitting, Deming and Stephan 1940), and transport planners did it to fit traffic matrices. Sinkhorn (1964) proved that the iteration converges for positive matrices, and Sinkhorn and Knopp (1967) characterized when a nonnegative matrix can be scaled. Its role in optimal transport is recent (Cuturi, 2013). Exercise 3 of §14 rakes a small table.

In machine learning — Cuturi’s “Sinkhorn distances” (2013)

Before 2013, transport distances between histograms (for instance bags of visual words, or images seen as histograms of pixel intensities) were attractive in machine learning but too slow: a $k$-nearest-neighbour classifier or a kernel method needs the distance between every pair of training examples, i.e. thousands of linear programs. M. Cuturi (Sinkhorn distances: lightspeed computation of optimal transport, NeurIPS 2013) proposed to replace each linear program by the entropic problem and to solve it with the iteration above. Two features made the difference: the iteration only uses matrix–vector products, which run in parallel on a GPU, and when all the histograms live on the same grid, $K$ is shared, so one histogram can be compared with many others at once (the vectors $v$ of the different problems become the columns of one matrix). OT4ML (p. 138) describes the effect: Sinkhorn “became a practical large-scale tool for machine learning, and also changed the way OT is viewed in ML, from a mostly geometric distance to a differentiable computational primitive”.

Pitfall — stopping too early, or measuring the wrong error
  • After a finite number of cycles, $P^{(\ell)}$ is not a coupling: its columns sum to $b$ but its rows do not sum to $a$. Measuring the column error after a column step always gives $0$ and tells you nothing; measure the row error.
  • If you need an exact coupling (to compute a cost $\ps{P}{C}$ that is guaranteed to be an upper bound of $L_C$, for instance), round the output to $\U(a,b)$ (Altschuler, Weed and Rigollet, NeurIPS 2017; CompOT Remark 4.6, pp. 69–70).
  • For a small $\eps$, the plain iteration divides by numbers that have underflowed to $0$: use the log domain (§6).
Method — Sinkhorn in five lines
  1. $K\leftarrow e^{-C/\eps}$ (entrywise), $v\leftarrow\ind_m$.
  2. Repeat: $u\leftarrow a/(Kv)$; $v\leftarrow b/(K\T u)$.
  3. Every few cycles, compute the row sums $u\odot(Kv)$ and stop when $\norm{u\odot(Kv)-a}_1<\text{tol}$.
  4. Return $P=\operatorname{diag}(u)K\operatorname{diag}(v)$ — or only $u,v$ if $nm$ is large.
  5. Value: $L^\eps_C=\ps{f}{a}+\ps{g}{b}$ with $f=\eps\log(u/a)$, $g=\eps\log(v/b)$, valid at convergence (§2).
Reflexes
  • Sinkhorn = alternate “fix the rows” / “fix the columns”; cost $O(nm)$ per cycle, parallel, GPU-friendly.
  • Stopping criterion → the marginal that was not just fixed.
  • Different initializations → same plan, scalings differing by $(\lambda u,v/\lambda)$.

For uniform $a=b=\frac1n\ind$ and a symmetric kernel whose rows all have the same sum $s$, how many cycles does Sinkhorn need from $v=\ind$?

Answer

One. $Kv=s\ind$, so $u=\frac1{ns}\ind$; then $K\T u=\frac1n\ind$ (columns of a symmetric matrix have the same sums as its rows), so $v=\ind$ again and $P=K/(ns)$ already has all row and column sums equal to $\frac1n$. Example: the running example’s kernel with $a=b=(\frac12,\frac12)$ gives $P=\frac{1}{2(1+e^{-2})}\begin{pmatrix}1&e^{-2}\\e^{-2}&1\end{pmatrix}$ after one cycle (Exercise 4 of §14).
