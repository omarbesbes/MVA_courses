8. Position: is the smoothness just position?

A position basis $\mP$ (one vector per grid position, per layer) is high-rank in early layers and collapses to about two dimensions in the last ones. In per-image PCA it shows up only in components 3 to 5, and the maps stay smooth when the position subspace is projected out.

The problem

The ViT adds position information at the input and every patch token is tied to a place in the grid. A smooth colour map over a grid could simply be that: tokens that are neighbours in the image have similar position codes. The paper tests this ("Just position?") in three steps: build a position basis, see how it changes with depth, check whether it explains the PCA maps.

The position basis $\mP$ and its two extractions

Positional basis extraction App. I · p. 45; §6 · p. 15

"For each layer, we extract positional embeddings from 1 million ImageNet images, yielding $\mA\in\R^{N\times t\times d}$ token representations [...]. We employ two approaches to recover the positional basis: Direct averaging. We compute the average embedding for each spatial position across all images: $\vp_i=\frac1N\sum_{k=1}^N\mA_{n,i}$ [...]. Linear classification. We train a linear classifier to predict token position from embeddings, yielding weight vectors $\vw_i$ for each position at each layer. Both methods produce highly consistent results [...]. We therefore choose to use the classifier weights as our primary positional basis." Main text: "a position encoding matrix $\mP\in\R^{256\times d}$ at each layer".

$\mP\in\R^{256\times d}$
row $i$ is the vector for grid position $i$ of the $16\times16$ grid, at a given layer. $256$ rows because only the patch tokens have a grid position.
direct averaging
$\vp_i$ is the mean activation of the token at position $i$ over images: whatever is constant across images at this position (content averages out). The paper writes $\mA_{n,i}$ with a sum over $k$ — an index slip: it should read $\frac1N\sum_{n=1}^N\mA_{n,i}$.
linear classification
a 256-way linear classifier $\hat i=\argmax_i\ps{\va}{\vw_i}$ (+bias, not mentioned). Its weight rows $\vw_i$ are the basis: a direction along which position $i$ is read out. Accuracy = fraction of tokens whose position is recovered.
Notation in the paper

The appendix uses $N$ and $n$ for the number of images and $t=261$ for tokens per image; only the $256$ patch tokens have a position. We write $N$ for the number of images.

Reminder — stable rank

For a matrix with singular values $\sigma_1\ge\sigma_2\ge\dots$, $\mathrm{srank}(\mP)=\norm{\mP}_F^2/\norm{\mP}_2^2=\sum_r\sigma_r^2/\sigma_1^2$. It is $1$ for a rank-one matrix, at most $\rank\mP$, and it counts "how many directions are as strong as the strongest". more

Place-cell code versus axis code

Two ways to code 256 positions in a vector space. Place code (O'Keefe's place cells): one direction per position, $\mP\approx\mI_{256}$; all 256 directions have the same strength, so after centring the stable rank is $255$ and the top-2 components explain only $2/255=0.8\%$ of the variance (computed in check_04.py). Axis code (Chang and Tsao for faces): two directions, the row coordinate and the column coordinate; $\mP$ has two columns that are ramps, stable rank $2$, $R^2=1$ (and the 256 positions form a flat sheet). The paper reads the evolution of Fig. 14 as a move from the first to the second.

What to look at: at 0 the position code is a place code: the sheet is a random cloud, stable rank is $255$. The mixture is a toy that we built; the real layers are in Figs. 14 and 15.

Inconsistency in Fig. 14 — layer axes, and a stable rank above 2 with $R^2\approx1$

(1) The two panels do not use the same layer axis: $R^2$ is plotted for layers $0$–$11$, stable rank for layers $1$–$12$. (2) The values are incompatible for one centred matrix. Let $R^2=(\sigma_1^2+\sigma_2^2)/\sum_r\sigma_r^2$. Then $\mathrm{srank}=\sum\sigma_r^2/\sigma_1^2=(\sigma_1^2+\sigma_2^2)/(R^2\sigma_1^2)\le2/R^2$, because $\sigma_2\le\sigma_1$. At $R^2\approx1$ this gives $\mathrm{srank}\le2$, while the last three layers read $2.8$, $2.6$, $2.7$. For all $12$ pairs of values the stable rank exceeds $2/R^2$ (check_04.py, figure below).

So the two panels are not computed on the same object: for instance the stable rank on the raw $\mP$ and $R^2$ on a centred (or otherwise processed) version, or a different definition of $R^2$. The text does not say. The qualitative message (rank decreases with depth towards a sheet) is unaffected; a quantitative claim such as "stable rank converges to 2" is not what the plot shows (it stays at about $2.6$–$2.8$).

Our reading — removing a linear subspace is not removing position

The projection removes what a linear classifier uses at one layer. The positional information that is left (nonlinearly coded, or in directions the classifier does not use) is not removed. And the map would be smooth even without any position code, since neighbouring patches share content. The experiment excludes the explanation "smooth because of the 2-D position sheet", which is what it is designed for. See page 6.

Reflex

When you see "the rank collapses to 2" → ask on which matrix (centred or not, which layers, which extraction) and compare with the bound $\mathrm{srank}\le2/R^2$.
