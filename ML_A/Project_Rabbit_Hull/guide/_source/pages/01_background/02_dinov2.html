2. DINOv2 and its evaluation

DINOv2 is trained without labels: a student network must reproduce the output of a slowly-moving teacher on different views of the same image, at the image level (DINO) and at the masked-patch level (iBOT), with a regulariser (KoLeo) that spreads features out. Its frozen features are then read by simple linear probes.

The paper does not train anything: it takes DINOv2 as given. This section gives the training objectives because §6 of the paper ("Toward interpolative geometry") appeals to them, and to explain why a linear probe on the output is meaningful.

2.1 DINO: self-distillation without labels

Problem. Learn features of images without labels. DINO (Caron et al. 2021, arXiv:2104.14294) uses self-distillation: two networks with the same architecture, a student and a teacher. The teacher's weights are an exponential moving average (EMA) of the student's: $\theta_t\leftarrow m\,\theta_t+(1-m)\theta_s$ with $m$ close to 1. Only the student receives gradients.

  1. From one image, draw several crops: 2 global (large, 224 px) and several local (small, 96 px).in the official DINOv2 configuration: 2 global crops with scale 0.32–1, 8 local crops with scale 0.05–0.32.
  2. The teacher processes the global crops only; the student processes all crops.forces "local to global" consistency: a small piece must predict what the whole shows.
  3. Each network ends with a head (an MLP then a layer of prototypes: learned vectors $\vp_1,\dots,\vp_K$). The head outputs $K$ scores, one per prototype, and a softmax turns them into a distribution $p$ over prototypes.a soft, learned clustering of the image into $K$ pseudo-classes.
  4. The loss is the cross-entropy $-\sum_k p^{\text{teacher}}_k\log p^{\text{student}}_k$ between the teacher's and the student's distributions.the student imitates the teacher; no label is involved.
  5. The teacher output is centred (a running mean is subtracted) and sharpened by a low temperature.centring prevents one prototype from dominating, sharpening prevents the uniform solution; together they prevent collapse (Caron et al.). DINOv2 uses centring (the official configuration offers Sinkhorn–Knopp as an option).
In the paper §6 · p. 16, footnote

"The global DINO head matches teacher representations using 128k prototypes, while the iBOT head performs masked prediction with its own 128k prototype vocabulary." The footnote: a DINO head "consisting of a 4096→4096→256 MLP that outputs scores over 128k prototypes", and an iBOT head with the same shape. "Both heads apply softmax normalization to produce probability distributions over their respective prototype vocabularies, effectively implementing implicit clustering with soft assignments."

Fact check against the official configuration

The file dinov2/configs/ssl_default_config.yaml of the official repository gives, for the DINO head, 65,536 prototypes, a bottleneck of 256, a hidden width of 2048 and 3 layers; the iBOT head has the same values and separate_head: false (it shares the DINO head). KoLeo weight 0.1, mask probability 0.5. This default file does not show the paper's 128k prototypes and 4096 width; the released checkpoints were possibly trained with other settings (the DINOv2 paper discusses 131,072 prototypes). We could not confirm the paper's footnote (two heads, 128k prototypes, 4096→4096→256) from the official files: read it as "according to the paper". Only the general idea (soft assignments to a large set of prototypes) matters for the paper's argument.

2.2 iBOT: the same idea on masked patches

DINO compares whole-image outputs. iBOT (Zhou et al. 2021, arXiv:2111.07832) adds a patch-level task: some patch tokens of the student's input are masked (replaced by a learned mask token); the student must output, for each masked patch, the same prototype distribution as the teacher gives for the unmasked patch. The loss is again a cross-entropy between softmaxes, now summed over masked patches. This forces patch tokens to carry local semantic content, which is why DINOv2 patch tokens are good for segmentation and depth. In DINOv2 each token of the masked crops has its own prototype head output (the paper says the iBOT head has "its own 128k prototype vocabulary"; the official default shares head parameters, see the check above).

2.3 KoLeo: spreading the features out

The Kozachenko–Leonenko (KoLeo) regulariser (Sablayrolles et al. 2018) is a differential-entropy estimator. For a batch of $n$ normalised feature vectors $\vx_i$ it is $-\frac1n\sum_i\log\big(\min_{j\neq i}\|\vx_i-\vx_j\|\big)$: it is large when some point has a very close neighbour. Minimising it pushes each vector away from its nearest neighbour, so features fill the sphere uniformly instead of clumping. DINOv2 adds it with weight 0.1 (official configuration). The paper cites it as "encouraging entropy maximization, promoting uniform distribution across the representation space while avoiding collapse" (§6 · p. 16).

Our reading — what the training facts do and do not say

The paper uses prototype heads and KoLeo to suggest that tokens are "mixtures of prototypes". The heads act on the network's output through a softmax; they say nothing yet about the geometry of the 768-dimensional token itself. See page 6.

2.4 Frozen features and linear probes

Problem. How to judge a representation learned without labels? Freeze the network and train only a linear probe: a matrix $\mW\in\R^{o\times d}$ mapping a feature (a token or a pooled vector) to $o$ outputs: class scores, a per-pixel class, a depth value. If a linear map suffices, the information is linearly accessible. DINOv2 is trained on a large automatically curated image set rather than uncurated data (Oquab et al. 2023, arXiv:2304.07193), and is meant to give features that work "across image distributions and tasks without finetuning".

The paper uses three probes on the output tokens (Fig. 2 · p. 3):

  • classification on ImageNet-1k: a linear head on the concatenation of the class token and the mean of the patch tokens (App. B.2 of the paper);
  • segmentation on ADE20K: a linear map from each patch token to a class;
  • depth estimation on NYU Depth v2: a linear map from each patch token to a depth value.

A probe is linear, so its output on the codes is $\mY=\mA\mW\T=\mZ(\mD\mW\T)$: the key identity of page 3.

Pitfall — probes show access, not use

A probe reads information the network keeps; it does not prove that the network uses it. The paper's "task-relevant" concepts are defined through the probe, i.e. relative to a linear read-out.
